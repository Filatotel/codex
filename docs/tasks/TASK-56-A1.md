## Required semantics

Implement the smallest additive contract that satisfies all of the following:

1. `ASSIGNMENT` can explicitly declare zero or more **required durable outputs**.
2. Each required durable output has a stable assignment-local identity so result coverage is deterministic rather than inferred from prose, ordering, filenames, paths, or artifact type guesses.
3. `EXECUTOR_RESULT` can bind each declared required durable output identity to a non-empty durable artifact reference.
4. For `EXECUTOR_RESULT.status = COMPLETE`, every declared required durable output must have exactly one valid binding.
5. A missing, blank, duplicate, ambiguous, or wrong-output binding cannot satisfy a required durable output.
6. `PARTIAL`, `BLOCKED`, and `FAILED` may truthfully return an incomplete subset; they must not be forced to fabricate references merely to satisfy structure.
7. An assignment with zero required durable outputs preserves current behavior.
8. Existing unrelated `resulting_state_refs`, `evidence_refs`, `related_artifacts`, and claim semantics must not be silently reinterpreted as durable-output coverage.
9. Schema validation and runtime validation must agree on the new structure and cardinality rules.
10. The existing post-spawn control path must not be able to accept a structurally invalid `COMPLETE` result whose assignment-required durable references are missing. Wire only this A1 completeness law into the existing validation path; do not introduce readback state or readback transition policy.

Prefer the smallest additive extension of the existing `ASSIGNMENT` / `EXECUTOR_RESULT` contracts. Do not create a new top-level artifact family merely to carry this mapping unless the current architecture makes the required law impossible without one.

Do not encode GitHub, Google Drive, filesystem paths, URLs, database keys, or any provider-specific storage semantics into the universal contract.
