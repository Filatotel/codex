# Develop Project Seed

## Purpose

Help an intelligent model turn early Owner material into a useful working project concept while preserving the difference between what the Owner actually said and what the model inferred or proposed.

This skill focuses native model reasoning. It does not replace reasoning with a form and it does not make an early idea authoritative merely because the working interpretation is durable.

## Execution contract

**Mandatory cognitive capability:** native model reasoning over the supplied Owner material and bounded relevant context.

**Durable output boundary:** the surrounding Foundation workflow may require `PROJECT_SEED` to be materialized through the generic durable-output path. Durable materialization does not create Owner/K0 authority or Canon authority.

**Evidence boundary:** ordinary inference may support a working interpretation, but unsupplied external facts, repository state, runtime state, feasibility claims, or current-world claims are not evidence merely because the model knows or expects them.

**Authority boundary:** this skill may interpret, reframe, propose, compare, and expose ambiguity. It may not invent Owner intent, accept Canon, issue an Owner decision, or authorize downstream Research or Production.

## Thinking guidance

Use judgment. Aim for the smallest coherent project seed that makes the idea easier to understand, challenge, and continue.

Consider, when material:

- the underlying objective rather than only the literal wording;
- intended users, beneficiaries, or value;
- protected Owner intent that later work must not casually erase;
- hard constraints and meaningful non-goals;
- decisions the Owner has already made;
- contradictions or tensions in the supplied material;
- hidden assumptions that could materially change the project;
- a useful project identity candidate or working name when one naturally exists;
- missing decisions only when different answers would materially change the project, route, authority, output, or next action.

Maintain these distinctions explicitly in reasoning and, where material, in the seed:

- explicit Owner statement;
- strongly implied context;
- model working interpretation;
- model proposal;
- unresolved material question.

A model proposal may improve the project. It remains a proposal until the Owner or another proper authority accepts it through the appropriate path.

Prefer a concise statement such as “I understand the project approximately as …” that the Owner can correct over asking the Owner to fill every potentially useful field.

Zero clarification questions is valid when the supplied material already supports a safe, useful working seed.

## Hard invariants

- MUST NOT invent Owner intent.
- MUST NOT relabel a model working interpretation or model proposal as an explicit Owner statement.
- MUST NOT promote `PROJECT_SEED` into accepted Canon or Owner/K0 authority.
- MUST NOT claim unsupplied external facts or feasibility as evidence.
- MUST preserve explicit Owner constraints, disagreements, and uncertainty that are material to the project.
- MUST NOT require global skill discovery merely to form a seed.

These invariants protect authority and evidence. They do not prohibit ideation, synthesis, reframing, cautious inference, or useful recommendations.

## Procedure

1. Read the supplied Owner material as ordinary language and identify the likely objective.
2. Form a bounded working interpretation using native reasoning.
3. Separate explicit Owner statements, strongly implied context, model interpretations, proposals, and unresolved material questions.
4. Check whether constraints, non-goals, contradictions, or hidden assumptions materially alter that interpretation.
5. Improve or simplify the framing when useful, labeling model-authored proposals as proposals.
6. Ask a bounded clarification only if the unresolved branch materially changes what Foundation should form next; otherwise continue with the safest useful interpretation.
7. Produce or refine non-authoritative `PROJECT_SEED` content for the Foundation workflow while preserving provenance.

## Stop condition

Stop when the seed is coherent enough to support outcome definition and consequential-unknown classification for the current formation stage. Do not chase exhaustive completeness.
